\section{Why only A0/A3}
Per the mandate's own Section~X priority order, engineering closure (CI, selector, E8 branch,
certification, evaluator audit) was prioritized above the full ablation ladder, and within Phase C,
A0/A3 were chosen as the two most informative single comparison (does the combined path+seionic
branch help at all, holding everything else fixed) given the compute available. Running the
intermediate points (A1, A2 alone) or the projection/rank/curriculum/selector combinations
(A4--A12) at dataset scale was not attempted --- correctly reported here as \texttt{OPEN}, not
silently absorbed into the A0/A3 comparison.

\section{What the A0/A3 comparison can and cannot support}
\textbf{Can:} demonstrate the architecture executes correctly end to end on real data with both
branches active (already shown extensively in engineering smoke tests, Phases B2--B5); give a
first, non-confirmatory look at whether adding the path+seionic branches moves validation MRR in
either direction on two real datasets.

\textbf{Cannot:} support any causal claim. Two seeds is explicitly insufficient for a variance
estimate (reported per-seed only, \S04); the A3 configuration ran on a 5,000-triple subsample of
each dataset's training split (a compute-budget deviation logged \emph{before} any A3 result was
generated, \texttt{preregistration.md} \S11), not the full training set A0 used --- so any MRR
difference between A0 and A3 is confounded with the training-data-size difference and cannot be
attributed to the architectural change alone. This confound is stated explicitly here, not hidden
in a footnote, and \texttt{04\_gate12\_confirmatory\_benchmark\_report.tex} repeats it next to the
actual numbers.

\section{Selector, geometric-loss, and E8 comparisons}
Each of these has real, executed evidence at the \emph{unit/engineering} level (learned selector:
14 tests including gold-path preservation after supervised warmup, \texttt{test\_selector.py};
geometric-loss weight-gating: 4 regression tests proving zero compute at zero weight,
\texttt{test\_seion\_kgr\_package.py}; E8 vs. 4 matched controls: 19 tests including 2 against the
real kernel, \texttt{test\_structural\_kernel.py}) but \textbf{none at dataset/ablation scale}.
Reported as \texttt{OPEN} for the causal question ("does X measurably help on real KG link
prediction"), \texttt{NUMERICALLY\_TESTED}/\texttt{DEFINITION} for the engineering-correctness
question ("does X work as specified").

\section{Causal interpretation limits, stated once more}
No result in this document, or this package, supports a statement of the form "SEION-KGR's
\{path reasoner / seionic branch / projection / E8 residual\} causes better link prediction." That
statement requires the full preregistered ladder at confirmatory scale (5 seeds, matched compute,
statistical testing per \texttt{preregistration.md} \S8) --- not executed in this campaign.
