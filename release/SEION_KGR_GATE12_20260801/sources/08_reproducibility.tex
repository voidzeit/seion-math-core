\section{Reference-vs-optimized and precision parity}
\begin{itemize}
  \item \texttt{seion\_kgr\_reference\_fp64.CPTernaryLaw} vs. \texttt{seion\_kgr.kernels.CPTernaryLaw}:
        identical copied weights, identical output to $\mathrm{atol}=10^{-4}$, across 6 random
        cases.
  \item BF16 on the real GPU vs. FP32 on CPU: relative error $<5\%$ (declared tolerance,
        appropriate for BF16's $\sim$3 decimal digits of precision).
  \item FP32 CPU vs. FP32 GPU (device-placement check, tighter): $\mathrm{atol}=10^{-5}$.
\end{itemize}

\section{Run identity}
Every run directory carries \texttt{configuration\_id} (SHA-256 of the resolved config, excluding
run-control fields: seed, out\_dir, resume, epochs, eval cadence/subset), a fresh
\texttt{execution\_id} per invocation, and \texttt{parent\_execution\_id} when resumed. A resume
whose \texttt{configuration\_id} does not match its parent checkpoint is rejected with a clear
error before any state is loaded --- live-verified, including catching and fixing two real bugs
during this campaign: \texttt{epochs} was initially (wrongly) part of the configuration hash,
which broke the ordinary "resume for more epochs" case; and the mismatch check initially ran
\emph{after} \texttt{load\_state\_dict}, surfacing a confusing raw PyTorch shape-mismatch error
instead of the intended message on a genuine architecture-mismatch resume. Both fixed and
reverified with real CLI runs, not just unit tests.

An out-dir reuse guard rejects a non-empty \texttt{--out\_dir} unless \texttt{--resume} is passed
--- live-verified: a fresh run into an occupied directory raises \texttt{FileExistsError} with an
explanatory message.

\section{Regeneration commands}
\begin{lstlisting}[basicstyle=\ttfamily\small]
# Full test suite
python -m pytest tests/kgr -q

# Both self-tests
python seion_kgr_reference_fp64.py --self_test
python seion_kgr_v26_train.py --self_test

# Tier 0 base-expert selection (FB15K-237, 1 epoch, GPU)
for BASE in complex distmult tucker cp; do
  python seion_kgr_v26_train.py --train data/FB15K-237/train.txt \
    --valid data/FB15K-237/valid.txt --test data/FB15K-237/test.txt \
    --out_dir runs/base_selection_$BASE --dim 64 --base_expert $BASE \
    --epochs 1 --batch_size 1024 --neg_k 64 --eval_max_queries 200 \
    --entity_block_eval 4096 --seed 1
done
\end{lstlisting}

\section{Limitations of this reproduction}
\begin{itemize}
  \item \texttt{E8\_Exact\_v18\_2/f\_E8.npy} (59MB) is not committed to git (same convention as
        \texttt{data/}); \texttt{E8\_exact}-variant tests and runs are skipped/unavailable without
        it placed locally.
  \item \texttt{data/} (FB15K-237, WN18RR, CoDEx-M, DB100K+, YAGO3-10) is not committed; must be
        fetched/placed locally.
  \item \texttt{runs/} and \texttt{campaigns/*/tier*/} are gitignored (checkpoints, large binaries)
        --- this package's \texttt{manifests/} directory carries the compact JSON summaries and
        hashes needed to audit what ran, not the checkpoints themselves.
\end{itemize}
